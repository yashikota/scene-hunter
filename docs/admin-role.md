# 管理専任の Admin

部屋作成時の UA から初期役割を選ぶ。PC は Admin、Android・iPhone・iPad 等は GM。
ロビーのボタンは一つで、GM のときは「管理者になる（ゲーム参加不可）」、Admin のときは「ゲームマスターになる」と表示し、押すと役割を切り替える。
GM 未指定の Admin はロビーだけを配信し、参加人数に含めず、ゲーム開始と写真アップロードを許可しない。
Admin が参加者を GM に指定すると、自分は Admin のまま新 GM の状態を購読する。
購読中の Admin が GM を選ぶと、現在の GM に署名つき要求を送り、通常の交代証で GM 資格を取得する。前 GM はプレイヤーとして入り直す。
切り替えはロビーに限り、ゲーム中はボタンを表示しない。
Admin は部屋に一人で、参加人数、写真提出、採点、順位には含めない。

GM は引き続き進行状態を保持し、お題撮影、ヒント生成、提出写真の選定、採点を担当する。
Admin は状態を購読し、開始、次ラウンド、最終結果、ロビー復帰を署名つきで GM に依頼する。
GM は受信時の epoch、phase、round、gameId と一致する要求だけを適用する。
Admin は参加リンク・QR・参加者の接続状態を確認し、HTTP API で解散できる。
Admin が画面を閉じても GM の進行には影響しない。GM の切断時に Admin が進行を引き継ぐ機能はない。

交代証の retainAdmin はサーバー署名の対象にする。
交代先が claim した時点で RoomRecord に adminPid を記録する。
元 GM は自分の期限内の旧 GM トークンで管理者用の参加証とトークンを受け取る。
交換前に Admin 資格を発行せず、通常参加からの自己昇格は認めない。
Admin の写真アップロードをサーバーで拒否し、GM は Admin の通常参加・提出イベントを無視する。

GM に状態保持を残すため変更範囲は小さいが、GM 端末の停止でゲームが止まる制約も残る。
PC に状態保持を移す案は、管理専任を補助管理とする今回の役割分担から外れるため採用しない。
管理者の端末移動と、途中ラウンドの強制中断は対象外とする。

既存の部屋は adminPid が無いまま動作し、通常の GM 交代も従来どおり参加者として入り直す。
初版の新規ラベルは日本語と英語を用意し、その他の言語では英語を使う。
